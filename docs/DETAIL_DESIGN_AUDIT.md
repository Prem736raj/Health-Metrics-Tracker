## Implementation boundaries and verification

- New scoped `ui/components/detail` API: independent day and night roles, per-feature accent/motif, original vector botanical geometry. Do not reuse completed full-screen artwork or copy their hub composition.
- Migrate detail-owned overrides to explicit roles. Shared helper callers outside the new scope must keep exact legacy behavior. No global AppColors, Color.kt, Type.kt, Theme.kt, nav route or dependency edits.
- Preserve all models, ViewModels, calculators, storage, data contracts, content strings/disclaimers, and existing medical/category thresholds. Cosmetic ARGB conversions, button labels, known icon actions and layout fixes are authorized presentation fixes.
- Before edits: snapshot current source and create hashes for all protected screens, forest helpers/assets, core/domain/data/ViewModels and build configuration. Then verify those unchanged.
- Validation: build + full unit suite; executable contrast checks for every new feature's day/night foreground/surface pairs (4.5 text, 3 icon/large); targeted Compose tests for theme boundaries/feature identities; real emulator navigation/results/tabs/screens in both modes; protected main-screen screenshot comparison where deterministic.
- Physical phone and every large-font/device configuration may remain unverified; final report must state actual coverage, incomplete items and any baseline warning/failure honestly.
